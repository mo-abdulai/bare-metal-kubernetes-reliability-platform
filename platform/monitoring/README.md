# Phase 6 Monitoring

OpsPulse Phase 6 uses a Kubernetes-native Prometheus stack for metrics and alerting.

## Stack

Helm chart:

- repository: `prometheus-community`
- chart: `kube-prometheus-stack`
- pinned chart version: `88.2.0`
- app version: `v0.93.0`

The chart provides:

- Prometheus
- Grafana
- Alertmanager
- Prometheus Operator
- node-exporter
- kube-state-metrics

No logging, tracing, GitOps, backup, database, or cache components are included in this phase.

## Raspberry Pi Sizing

Live node capacity inspected before deployment:

| Node | CPU | Memory | Ephemeral storage | Notes |
| --- | ---: | ---: | ---: | --- |
| `homepi` | 4 cores | ~7.6 GiB | ~28 GiB | control-plane, suitable for single monitoring control-plane workloads |
| `workpi` | 4 cores | ~905 MiB | ~28 GiB | memory-constrained worker; avoid heavy monitoring pods |

Current usage from metrics-server before monitoring:

| Node | CPU | Memory |
| --- | ---: | ---: |
| `homepi` | ~263m / 6% | ~1755 MiB / 22% |
| `workpi` | ~97m / 2% | ~500 MiB / 55% |

`values.yaml` therefore schedules Prometheus, Grafana, Alertmanager, kube-state-metrics, and the operator on `homepi` and keeps `node-exporter` as the only per-node monitoring DaemonSet.

Prometheus retention is intentionally short:

- time retention: `3d`
- size retention: `2GB`
- PVC: `4Gi` on `local-path`

## Deploy

```bash
make deploy-monitoring KUBECTL='ssh mo-abdulai@homepi.local sudo k3s kubectl'
```

Equivalent Helm command:

```bash
helm upgrade --install kube-prometheus-stack \
  prometheus-community/kube-prometheus-stack \
  --version 88.2.0 \
  --namespace monitoring \
  --create-namespace \
  --values platform/monitoring/values.yaml
```

Apply project-specific resources after Helm:

```bash
kubectl apply -f platform/monitoring/servicemonitor-opspulse-api.yaml
kubectl apply -f platform/monitoring/rules/opspulse-alerts.yaml
kubectl apply -f platform/monitoring/dashboards/opspulse-operations-dashboard.yaml
```

## Access

Prometheus and Grafana are ClusterIP only. Use port-forwarding:

```bash
kubectl -n monitoring port-forward svc/kube-prometheus-stack-prometheus 9090:9090
kubectl -n monitoring port-forward svc/kube-prometheus-stack-grafana 3001:80
kubectl -n monitoring port-forward svc/kube-prometheus-stack-alertmanager 9093:9093
```

Grafana credentials are generated by the chart and stored in a Kubernetes Secret. Do not commit credentials.

```bash
kubectl -n monitoring get secret kube-prometheus-stack-grafana \
  -o jsonpath='{.data.admin-password}' | base64 -d
```

## PromQL

Ready node count:

```promql
sum(kube_node_status_condition{condition="Ready",status="true"})
```

CPU utilization by node:

```promql
100 * (1 - avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])))
```

Memory utilization by node:

```promql
100 * (1 - ((node_memory_MemAvailable_bytes or node_memory_MemFree_bytes) / node_memory_MemTotal_bytes))
```

Filesystem utilization by node/mount:

```promql
max by (instance, mountpoint) (100 * (1 - (node_filesystem_avail_bytes{fstype!~"tmpfs|overlay|squashfs|proc|sysfs|devtmpfs"} / node_filesystem_size_bytes{fstype!~"tmpfs|overlay|squashfs|proc|sysfs|devtmpfs"})))
```

Pod restart counts:

```promql
kube_pod_container_status_restarts_total{namespace="opspulse"}
```

Deployment desired replicas:

```promql
kube_deployment_spec_replicas{namespace="opspulse"}
```

Deployment available replicas:

```promql
kube_deployment_status_replicas_available{namespace="opspulse"}
```

OpsPulse API scrape status:

```promql
up{job="opspulse-api"}
```

OpsPulse API request rate:

```promql
sum(rate(opspulse_api_http_requests_total[5m])) by (status_code)
```

OpsPulse API 5xx rate:

```promql
sum(rate(opspulse_api_http_requests_total{status_code=~"5.."}[5m]))
```

OpsPulse API p95 duration:

```promql
histogram_quantile(0.95, sum(rate(opspulse_api_http_request_duration_seconds_bucket[5m])) by (le))
```
